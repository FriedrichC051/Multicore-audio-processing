# 实验报告：实时块约束下多声源 HRIR 的冷热分层驻留

头在转时，方向系数要不要每一小段都重新送到显卡。一路声音上，省下的传送只有几十微秒，播放预算是 21.33 ms，看不出用处。游戏和虚拟现实里常常是十几路、几十路一起响。本报告要回答的是：常用方向留在显卡上、只在显卡里混合相邻系数，和每段从主机重送，在多路实时块里差多少；热方向留几个；网格变疏以后未命中和误差怎么变；先混合系数再卷积，和先卷积再混合输出，哪一种更省时间。

数字来自 `results/` 下已有的表，本报告没有重新计时。测量在 WSL2 和 RTX 4060 上完成。GPU 的启动和拷贝经过 `/dev/dxg` 由 Windows 驱动转发，绝对微秒数不能写成裸机规律。同一次运行里两种做法被加上同一截转发时间，快慢差额仍然可以读。同一配置跨文件再跑，端到端 p50 会自己挪动几十微秒：32 路、8 个热方向、5 度网格、先混合系数，在三份表里分别是 266.14 μs、340.77 μs 和 322.94 μs。下面凡是给差额，都取同一张表里的两行。

播放时长只由 1024 / 48000 = 21.33 ms（21333.33 μs）计算。耳机经 WSLg 的延迟不计入。没有做试听。OpenCL 在这台机器上没有厂商 ICD，`clGetPlatformIDs` 返回 −1001，没有对应耗时。

## 结论

- 整圈短系数放在显存里，主机重送就从“每段每路换方向都传一套”变成“只有甩进冷区的那两路各传一次”。8 路从 5170 次降到 2 次，同一次运行的端到端 p50 从 345.06 μs 降到 231.30 μs。32 路从 29020 次降到 2 次，p50 从 911.84 μs 降到 266.14 μs。两种做法的 p99 都远低于 21.33 ms，超时段都是 0。省下的是传送，不是把本来会错过的播放补回来。
- 16 个方向放进了常量内存（16 × 左右耳 × 512 点 = 64 KB）。热方向从 2 改到 16，主机重送次数不变，因为其余方向已经在全局内存里。8 路分层的 p50 落在 212.77–234.59 μs，32 路落在 266.14–321.79 μs。32 路这一次较短的是 8 个热方向。这是时延和常量内存占用的近似折中，不是唯一最优。
- 单路、8 个热方向：重送 p50 224.93 μs，分层 187.68 μs，少 37.25 μs，占 21.33 ms 的 0.17%。主实验必须是多路，单路省时说明不了应用价值。
- 甩到 175° 的声源落在没有存放系数的 [170°, 190°)，整套系数从主机送入。相对同一次混合的信噪比约 139 dB，没有用旁边网格上的系数硬混。
- 网格从 5° 放到 15°，这套慢转运动的未命中重送仍是 2 次，相对真实方位的近似信噪比从约 26 dB 降到约 18 dB。放到 30°，160° 附近被 150° 和冷区里的 180° 夹住，未命中重送变成 8 路 359 次、32 路 1969 次，近似信噪比再降到约 16 dB。5° 上就已经只有二十多 dB，是因为两套系数按比例相加抹不平延迟的跳变。
- 先卷积再混合输出，和先混合系数再卷积，波形互比在 8 路是 138.98 dB、32 路是 137.71 dB。8 路 p50 只差 1.34 μs，看不出多一次卷积。32 路差 82.14 μs，这是同一次运行里多一次卷积的时间。

更早的块长、阶数和通路扫描不在这次重做。它们留下的、现在还用得上的结论写在最后一节：选定的卷积是 FP32 展开内核、块大小 512；一路默认块上 GPU 不划算；声源变多以后 GPU 耗时涨得更慢。交点恰好落在 8 个声源，是这台 WSL 上的读数。

## 做法

默认块长 1024，采样率 48000 Hz，滤波器 512 点。左右耳分开。一个方向约 4 KB。卷积沿用设备内选定的展开内核，输入历史留在显存。预热 20 段，计时 1000 段。时间取这段的 p50、p99 和最大值。超过 21333.33 μs 的段计为超时段。

系数随方位平滑变化：越偏一侧，一路的延迟和增益按固定规律变，另一路相反。它不是某一次人头测量。标准答案是 CPU 双精度上做同样的运算再卷积。

三层存放：

- 热。从 0° 起连续的网格点，放进常量内存。主实验扫 2、4、8、16 个。后面的网格和混合实验固定 8 个。
- 温。这一圈其余网格点，放在全局内存。命中不经主机。
- 冷。方位落在 [170°, 190°)，或夹住它的网格点落在这段里，留在主机。未命中才整套上传。上传一次之后，方位不变就不再传。

运动在各路之间分开。8 路和 32 路里，一路停在 0°；末尾两路先慢转，到计时段第 100 段跳到 175° 并停住；其余路在 [0°, 160°] 内每段转 1°，碰到边界就折返。单路对照没有静止路，也没有甩头，只用来看省时占播放预算的比例。

两种策略：

- 重送。方向一变，就从主机拷一套新系数。
- 分层。热区或温区里相邻两套按比例相加后再卷积，主机只上传混合比例和这一段的新样本。冷区才重送。

## 此前的卷积与通路

下面的数字来自 `results/phase1_results.md`、`results/phase2_results.md`、`results/phase3_results.md`。通路和区间的图在 `report/figures/`，叙述见 `report/技术报告.md`。这一节只保留后来实验还靠得住的结论。

设备内计时不含搬运。选定 `f32_unroll`、块大小 512：p50 21.50 μs，相对双精度的信噪比 136.64 dB。块大小 1024 的 p50 也是 21.50 μs，相差不超过 1 μs 时取更小的块。Q15 是 67.87 dB，int8 DP4A 是 23.57 dB，都不进入选定集合。这条信号的输出约在 [−1, 1)，Q15 的 int32 溢出样本为 0。Nsight Compute 在这块 WSL2 上采不到硬件计数器，块大小的结论来自这四行耗时。`cudaHostRegister` 探针成功。

端到端默认点是块长 1024、阶数 512、1 个声源、历史留在显存：p50 112.83 μs，p99 590.98 μs，AVX2 23.66 μs，超时段 0。差距大约 90 μs。块长 128–4096 和阶数 128–4096 的时域端到端，在那次扫描里都慢于 AVX2。FIR = 4096 时 kernel p50 171.87 μs 已经快过 AVX2 的 205.76 μs，端到端仍是 229.57 μs。cuFFT 不含搬运的计算段从 FIR 1024 起快过时域 kernel，端到端在扫过的阶数上没有更快。攒 4 块再做 FFT 的端到端 p50 是 64659.78 μs，里面含 3 块等待，相对单块播放时长 250 组全部欠载。

声源从 1 增到 32 时，AVX2 的 p50 从 23.67 μs 涨到 799.25 μs，CUDA 端到端从 168.16 μs 涨到 470.91 μs。在这台 WSL 上，p50 从 8 个声源起快过 AVX2，8、16、32 的 p99 都低于播放时长。这个交点会被每块一次的转发延迟往后推，不能写成硬件规律。声源变多以后 GPU 耗时涨得更慢，这个方向还在：转发大体按块收取，解释不了两条线谁涨得更快。每块更换一套系数的端到端 p50 是 167.04 μs，比系数固定的 112.83 μs 高 54.21 μs。stream 深度 1、2、3 是 112.83、113.86、127.65 μs。

四条通路在 1 个声源上的端到端 p50：可分页同步拷贝 121.63 μs，注册后异步拷贝 122.18 μs，映射零拷贝 27.65 μs，历史留在显存 126.40 μs。信噪比都是 136.64 dB。拷贝占端到端 p50 的比例分别是 0.80、0.36、0、0.63。映射零拷贝比 AVX2 的 23.09 μs 只慢 4.56 μs，这个名次太近，换一台没有 `/dev/dxg` 的机器可能反过来。8 个声源时，可分页整窗拷贝 166.53 μs 和历史留在显存 148.96 μs 都快过 AVX2 的 182.46 μs。后来的冷热实验沿用历史留在显存这一条，不再重扫通路。

## 和已有文献的关系

先前调研的文献能给方向上的佐证，给不了上面这些数字。冷热驻留本身，以及“留几个热方向几乎不改变主机重送”，是这次新测出来的。

### 一致的部分

短滤波器、小块音频上，显卡的优势不在单路乘法。[Carvalho、Ilic 和 Sousa 的综述](https://doi.org/10.1145/3830900)收进一条旧结果：Smirnov 和 Chiueh 的着色器实现里，线性卷积要到输入和滤波器都超过约 6 万点，GPU 才快过向量化的 CPU。本报告的 512 点、一路、块长 1024，端到端 112.83 μs，AVX2 是 23.66 μs，方向相同。声源从 1 增到 32 时，AVX2 从 23.67 μs 涨到 799.25 μs，CUDA 从 168.16 μs 涨到 470.91 μs，也符合综述里“路数多了再交给 GPU”的趋势。交点恰好落在 8 路，仍是这台 WSL 的读数，综述里没有这个数。

来回搬运有大约 0.1 ms 的底。[Renney、Mitchell 和 Gaster](https://nime.org/proceedings/2020/nime2020_paper39.pdf)在空内核加往返拷贝上测到，这块底大约 0.1 ms，随显卡变化。本报告一路换一次系数多出来 54.21 μs，单路改成驻留只少 37.25 μs，都在这个量级，也都远小于 21.33 ms。他们比的是交互乐器能接受的延迟和抖动，块长 512 以上在他们的标准里已经偏长。本报告的 21.33 ms 是这一小段必须播完的期限。两篇文章的及格线不一样，只能互相说明搬运底噪相对这一小段的播放时间很小。

大变换会先把期限吃掉。[Gardner](https://aes.org/e-lib/browse.cfm?elib=7957)在 1995 年指出，冲激响应开头若也去等一次大变换，延迟先被变换块长占掉。本报告把 4 块攒起来再做 FFT，端到端 64659.78 μs，250 组全部超过单块的 21.33 ms。这是在本机上再次看到他的结论。

直接把两套脉冲响应按比例相加，抹不平延迟。[Cuevas-Rodríguez 等人的 3D Tune-In](https://doi.org/10.1371/journal.pone.0211899)用邻近方向的头相关脉冲响应做重心插值，同时把耳间延迟拆出去单独处理。他们写明：两套耳间延迟不同的脉冲响应直接相加，会出现梳状滤波。[Ramos、Cobos、Bank 和 Belloch](https://doi.org/10.1109/LSP.2017.2741724)把整套响应收成可并行的二阶滤波节，插值的是频率、增益和 Q，并说明这种参数形式才适合线性插值。本报告即使用 5 度网格，相对真实方位也只有 26.08 dB（8 路）和 25.78 dB（32 路），数值实现本身仍有约 139 dB。原因和他们说的是同一件事。26 dB、18 dB、16 dB 是这套合成系数上的读数，不是他们听力实验的复现。

### 文献没有测过的部分

这些论文换方向时，都默认系数已经在计算设备上，然后继续算。

Ramos 等人在 GPU 上同时渲染很多路，论文写的规模是当时的高端显卡上最多 1230 路。那是短的二阶节，不是 512 点卷积，也没有把“这一小段从主机重送一套系数”计进时间。3D Tune-In 的分段卷积同样假定这一帧的脉冲响应已经在手上。[Wefers](https://doi.org/10.18154/rwth-2015-02185)讨论了运行中更换滤波器，场景是长冲激响应的频域分段卷积。[pyBinSim](https://aes.org/e-lib/browse.cfm?elib=18721)把直达声、早期反射和后期混响拆开，长的那段可以放在 CUDA 上。他们拆的是声音的哪一段，不是方位系数放在常量内存、显存还是主机。

他们能说明系数在设备上之后，混合和多路卷积做得到。上面的重送次数表不在他们的测量里。[Rosseel 和 van Waterschoot](https://arxiv.org/abs/2509.04390)测的是很长混响上的分段卷积，块长大于 128 点后 GPU 才能实时。那是另一类滤波器，既不支持也不否定本报告的驻留结果。

### 本实验新看到的

真正省下来的是整圈留在显存里，不是常量内存里多留几个方向。8 路的主机重送从 5170 次降到 2 次，同一次运行的 p50 从 345.06 μs 降到 231.30 μs。32 路从 29020 次降到 2 次，p50 从 911.84 μs 降到 266.14 μs。两边都没有超时段。16 个方向放进了 64 KB 常量内存；热方向从 2 改到 16，重送次数不变，因为其余方向已经在全局内存里。小内存装不下、所以要找留几个最划算，这个矛盾在 512 点、一圈水平网格上并不出现在显存。装不下的只是常量内存，而它带来的时间差只有几十微秒，和 WSL 上重复运行的起伏同一量级。

网格变疏先改变未命中，再改变误差。15 度时慢转仍被两个网格点夹住，未命中重送还是 2 次，近似信噪比降到约 18 dB。30 度时，160° 附近被 150° 和冷区里的 180° 夹住，未命中重送变成 8 路 359 次、32 路 1969 次，信噪比再降到约 16 dB。文献说明网格越疏插值越差。疏到把下一格推进没存放的缺口，重送次数会跳上去，这是这套冷区规则下新测到的。

先卷积再混合输出，波形和先混合系数几乎相同，时间只在路数多时才显出来。两种输出互比，8 路 138.98 dB，32 路 137.71 dB。8 路只差 1.34 μs，32 路差 82.14 μs。3D Tune-In 对很短的二阶节也做了新旧系数各算一次再交叉淡化，并说这个代价不大。本报告补上的是 512 点卷积：路数少时这个代价测不出来，32 路才到几十微秒，仍然远小于 21.33 ms。
