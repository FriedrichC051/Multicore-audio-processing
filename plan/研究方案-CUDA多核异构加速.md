# 研究方案：CUDA 卸载 HRIR 卷积的实时有效工作区间

> 课程：基于多核加速的空间音频立体声音效处理（高峰体验课）
> 研究问题：CUDA 卸载 HRIR 卷积时，在一块音频必须在其播放时长内算完的约束下，有效工作区间在哪里
> 版本：v5（主语改回 CUDA：实验一为 kernel 侧主工作，实验三只保留 CPU–GPU 通路，2026-10-15）

---

## 一、研究问题

课程要深入的是异构加速，以及核与核之间的同步和数据交换。同构多核已由第 5、6 次课的 OpenMP 作业完成。本方案的异构实现用 CUDA，问题收成一句：

**CUDA 卸载 HRIR 卷积时，在「一块必须在其播放时长内算完」的约束下，有效工作区间在哪里？**

区间由两段 CUDA 工作一起划出：

1. **Kernel 侧（实验一，主要实现工作）**：内存层次、占用率和指令把设备内的计算天花板抬到多高。这里比较全局内存、常量内存、共享内存、FP32、Q15 和 int8 DP4A。
2. **系统侧（实验二、实验三）**：这块天花板从何种块长、HRIR 阶数、声源数开始，能够体现在含 PCIe 搬运的端到端延迟上，并快于 AVX2。实验三说明差距花在 CUDA 的哪一种主机–设备通路上。

课程默认规模说明为什么区间本身就是结论。第 5 次课实测（48 kHz、16-bit 双声道、FIR 512、BUF 1024、312 块）：串行 795 ms，双核 OpenMP 269 ms，平均每块约 2.5 ms 和 0.9 ms。1024 点的播放时长在 44.1 kHz 下是 23.22 ms，在 48 kHz 下是 21.33 ms。一块运算量约为 \(1024 \times 512 \times 2 \approx 10^6\) 次乘累加，在 RTX 4060 上是微秒级，kernel 启动和一次 PCIe 往返是固定开销。因此设备内加速比和端到端延迟要分开报：前者是 CUDA kernel 的成绩，后者才决定这个规模落不落在有效区间里。

主结果是两张图：

- 实验一：同一卷积上，各 CUDA 实现的设备内耗时和相对双精度的 SNR
- 实验二：横轴为块长、阶数、声源数，纵轴为 CUDA 与 AVX2 的每块延迟分布，并标出该块播放时长

预期（待测量，不作为前提）：

- 课程默认规模下，CUDA 设备内耗时明显短于 AVX2，端到端却慢于 AVX2，或优势小到被抖动吃掉
- 声源数增多、HRIR 变长之后，CUDA 端到端进入有效区间
- 历史留在显存、只传送新的一块，能把区间的左边界往更小的规模推
- 多 stream 重叠传输和计算能提高吞吐，同时把端到端延迟抬高数块

## 三、对照基线

第 2–4 次课的产物收成一张 CPU 对照表，供实验二做分母：

- Overlap-Add：BUF = 1024，FIRSZ = 512，HIST = 511
- 双精度浮点参照、Q15（课程写法：`int32` 累加后 `>> 15`）、AVX2 + FMA（`-O3 -mavx2 -mfma`）
- 每个版本相对双精度的 SNR，以及处理同样块数的每块耗时

512 次 Q15 乘加在满幅时会超出 `int32`（单次乘积最大约 \(2^{30}\)，512 次约 \(2^{39}\)）。课程代码能工作，是因为 HRIR 幅度远小于满幅。基线里增加一列 `int64` 累加，用来判断现有 `int32` 写法有没有溢出造成的 SNR 损失。

标量、定点、SIMD 不作为独立研究层次。交错存储和平面存储若在 AVX2 上有明显差别，在对照表里留一行。

## 四、三组实验

### 实验一：CUDA kernel 把计算天花板抬到多高

这是本方案的主要实现工作。输入、系数、历史预先放在显存，不计 PCIe。目的是把时域卷积的 CUDA 实现做到可解释：哪一种内存层次、哪一种指令在 RTX 4060 上真正抬高天花板，精度付出多少。实验二和实验三使用其中天花板最高且 SNR 可接受的 kernel。

设备内优化沿这几步测量，每步都报耗时和 SNR：

1. 每线程一个输出点，全局内存直读
2. 系数广播：同一时刻一个 warp 读同一个抽头时放入常量内存；否则把系数装进共享内存
3. 输入分块进共享内存，块内复用
4. 循环展开与占用率调整，用 Nsight Compute 说明瓶颈是算力、带宽还是启动延迟

精度–性能对照（同一卷积、同一组输入）：

| CUDA 路径 | 做法 | 要报的数 |
|---|---|---|
| FP32 | 浮点乘加 | 耗时、相对双精度的 SNR |
| Q15 | int16 乘，**int64 累加**后右移 15 位；另报 int32 累加是否溢出 | 耗时、SNR、溢出样本数 |
| int8 DP4A | `__dp4a` 是 4 路 **int8** 点积，不是 int16。音频和 HRIR 要再量化到 int8 | 耗时、相对双精度的 SNR（与 Q15 分开报） |

DP4A 是否快于 FP32，在 RTX 4060（Ada，SM 8.9，FP32 吞吐高）上作为结果来写。int8 的 512 次乘加（最大约 \(127^2 \times 512 \approx 8\times 10^6\)）落在 int32 累加范围内。块只有约 \(10^6\) 次乘加时，roofline 可能显示启动或延迟占主导，这个结果写入实验一，用来解释哪些优化对这么小的 kernel 已经没有头寸。

频域卷积的设备侧实现放在实验二，与这里的时域天花板比较，同时计入 FFT 块长带来的算法延迟。

### 实验二：这条 CUDA 路径的有效工作区间

同一块数据从主机内存出发，测到结果回到主机为止。CUDA 路径使用实验一选定的 kernel。对照是第三节的 AVX2。落在有效区间内，指 p99 低于该块播放时长，并且 p50 快于 AVX2。

横轴（逐个变化，其余保持默认）：

- 块长 BUF。播放时长预算等于 \(\mathrm{BUF}/F_s\)，随块长一起变
- HRIR 阶数。短阶用实验一的时域 kernel；阶数拉长后加入 cuFFT 分段卷积，画出时域/频域两条曲线。更大的 FFT 块会抬高算法延迟，曲线上同时标出延迟
- 声源数。每个声源整段卷积交给 CPU 或 GPU，在 GPU 上按声源批处理。不把一块里的采样点拆开分给两边
- 方位每块变化一次。最近邻换一套 HRIR，系数经一次额外的主机到设备传输。这是第 4 次课移动声源在 CUDA 路径上的落点

多 stream 把传输和计算重叠时，流水线要压住 2–3 块才填得满。报告把流水线深度和由此增加的端到端延迟画在同一张图上，并和该块的播放时长比较。

### 实验三：CUDA 数据通路如何把天花板传到端到端

只比较主机内存进入 CUDA 之后的搬运。进程间 pipe 与共享内存的差别由课程作业覆盖，不在这里再测一遍。实验输入视为已经在主机内存中；若缓冲来自 POSIX 共享内存，它只作为下面某条 CUDA 通路的主机指针。

| CUDA 通路 | 每块实际搬运 |
|---|---|
| 可分页内存 `cudaMemcpy` | 主机到设备、设备到主机各一次；驱动内部还可能再经一块分页锁定缓冲 |
| `cudaHostRegister` 后 `cudaMemcpyAsync` | 异步拷贝，可与别的块上的 kernel 重叠 |
| `cudaHostGetDevicePointer` 映射零拷贝 | kernel 直接读主机，无显式拷贝，每次访问走 PCIe |
| 历史留在显存 | 只把本块新的 BUF 帧传到设备；511 点历史和重叠尾留在设备上；只把 BUF 帧结果传回 |

历史留在显存是这一组的重点。重叠相加的尾部留在设备上，每块少一次尾部往返。各通路都用实验一的同一个 kernel，这样延迟差可以归因到通路，而不是 kernel 又改了。

第 7–8 周先做探针：WSL2 里对 `mmap` 得到的主机缓冲调用 `cudaHostRegister` 能否成功。注册路径和映射路径都依赖它。失败则这两条改为在原生 Linux 上补测，或记为环境限制；普通拷贝和历史留显存照常做。

### 指标

每个配置都过正确性，再报性能：

- 相对双精度参照的 SNR。定点路径同时写明累加位宽和溢出样本数
- 每块墙钟时间的 p50、p99、最大值，样本数不少于 1000 块。预热块不计入
- 欠载次数：处理时间超过该块播放时长 \(\mathrm{BUF}/F_s\) 的块数
- 实验三额外报传输字节数，以及这一段占端到端延迟的比例
- 实验一额外报设备内耗时，与实验二的端到端耗时并排，用来看出 PCIe 和启动吃掉了多少

OpenCL 不单独成层：用与 CUDA 相同的卷积、相同的块长/阶数/声源数，做一版端到端（历史留在设备侧，若运行时支持等价的缓冲）。对比 p99、欠载次数和代码量，用来回答第 5 次课里 CUDA 相对开放标准的性能差和实现代价。

## 五、创新点

1. **CUDA 时域卷积的设备内天花板。** 在同一 HRIR 卷积上量化内存层次和指令的收益，并按指令的真实宽度做定点：FP32、Q15（int64 累加）、int8 DP4A，同时给耗时和 SNR。
2. **CUDA 卸载的有效工作区间。** 用块长、阶数（含 cuFFT）和声源数划出端到端快于 AVX2、且 p99 低于播放时长的范围。设备内加速比和端到端延迟分开呈现。
3. **CUDA 主机–设备通路。** 普通拷贝、注册后的异步拷贝、映射零拷贝、历史留在显存四条通路，解释天花板有多少能到达端到端。多 stream 的流水线深度单独标出延迟代价。

## 八、风险与提前验证

- **计算规模。** 默认块上 CUDA 设备内很快、端到端仍可能慢于 AVX2。这是有效区间要测量的边界，实验二的横轴就是为这个结果准备的。报告按数据写。
- **WSL2 与 CUDA。** 本机 RTX 4060（Ada，SM 8.9）在 WSL2 下可用，支持 DP4A。`cudaHostRegister` 能否用在 `mmap` 缓冲上，第 7–8 周探针确定。失败则实验三少两条通路，kernel 与其余通路仍能回答区间问题。
- **Nsight。** 用于实验一。WSL2 上硬件计数器若受限，roofline 改为在 Windows 侧补，或退化为用耗时和带宽估算说明瓶颈。
- **音频播放。** 不把 WSLg 播放纳入播放时长的判定。实时判定只看 CUDA 渲染路径自己的每块墙钟。
- **进度。** 实验一占三周，是交付主体。cuFFT 只在实验二的阶数轴上出现。OpenCL 只做一条端到端，不移植实验一的每一步。方位扫描做到最近邻换系数。
