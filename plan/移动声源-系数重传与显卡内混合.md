# 实时块约束下多声源头相关脉冲响应的冷热分层驻留与按需传输

头在转时，方向系数要不要每一小段都重新送到显卡。只做一路声音时，省下的传送大约 54 微秒，播放预算有 21333 微秒，看不出用处。游戏和虚拟现实里常常是十几路、几十路一起响，头或人一动，很多路都要换方向。这个工作以多路实时渲染为场景，比较两种做法：每一路都把新系数从主机送上显卡，还是把常用方向留在显卡上、只在显卡里把相邻两套系数混出来。要找的是留多少个方向最划算。留得太少，经常要重送，时间省不下；留得太多，最靠近计算的那块小内存装不下。整张显存装得下一整圈短系数，装不下的是大约 64 KB 的常量内存，大概只能放十几个方向。CPU 上做混合是为了声音连续，系数本来就在内存里，没有传送这一步，代价是多算一次。GPU 上多出来的就是这次传送，所以才要找这个折中。CPU 和显卡谁做乘法更快，只用来决定这一小段放在哪边算，不再当作要证明的结论。这对应课程里头相关传输函数热数据驻留、冷热分开存放的研究点，落在 CUDA 上，不另做嵌入式片上内存。

测量仍在现有 WSL2 和 RTX 4060 上进行。GPU 的启动和拷贝要经过 Windows 转发，绝对微秒数不能写成裸机规律。比较在同一台机器上完成，两种做法都被加上同一截转发时间，快慢差额仍然有效。

## 和已有工作的关系

前人把两件事分开做了，没有放在“这一小段必须按时播完、而且有很多路”里比较。

方向怎么混才像真的。[Cuevas-Rodríguez 等人的 3D Tune-In 工具包](https://doi.org/10.1371/journal.pone.0211899)用分段频域卷积做实时双耳渲染，方位不在测量网格上时，用附近的头相关脉冲响应配出来（PLoS ONE，2019）。[Ramos、Cobos、Bank 和 Belloch](https://doi.org/10.1109/LSP.2017.2741724)把整套头相关传输函数收成可以并行的二阶滤波节，参数可以线性插值，并在 GPU 上同时渲染很多路声音（IEEE Signal Processing Letters，2017）。他们比的是方向像不像、能撑多少路，默认系数已经在计算设备上。CPU 上的混合也是为了换方向时声音不断开，系数就在内存里，不存在每小段重送。

显卡适合算很长的混响和很多路，不适合每一小段都重新开工。[Wefers 的博士论文](https://doi.org/10.18154/rwth-2015-02185)把实时卷积分成均匀分段、非均匀分段和整段傅里叶变换，并讨论了滤波器随时间变化的情形（亚琛工大，2015）。[Gardner](https://aes.org/e-lib/browse.cfm?elib=7957)在 1995 年指出，冲激响应的开头若也拿去等一次大变换，延迟会先被变换块长吃掉（JAES）。[Rosseel 和 van Waterschoot](https://arxiv.org/abs/2509.04390)在很长混响上测到，块长大于 128 点后 GPU 分段卷积才能实时（2025 年预印本）。[Renney、Gaster 和 Mitchell](https://nime.org/proceedings/2020/nime2020_paper39.pdf)量过 GPU 音频的启动和搬运底噪大约 0.1 毫秒（NIME，2020）。[Carvalho、Ilic 和 Sousa 的综述](https://doi.org/10.1145/3830900)把这些结果收在一起：短滤波器、小音频块留给 CPU，长滤波器和很多路交给 GPU（ACM Computing Surveys，2026）。[Neidhardt、Klein、Knoop 和 Köllmer 的 pyBinSim](https://aes.org/e-lib/browse.cfm?elib=18721)把直达声、早期反射和后期混响拆开，长的那段可以放在 CUDA 上（AES 142nd Convention，2017；程序在 [GitHub](https://github.com/tuil-emt/pybinsim)）。这些工作换方向时假定换完就继续算，没有量过很多路同时重送一套 512 点系数会不会把播放预算用完，也没有在 GPU 上找“留几个方向最划算”。

本工作不发明新的听感模型，也不重复“谁更快”的扫描。它把传送代价、邻近方向可以混合、以及小块快内存装得下几个方向，接在同一个截止时间和多路场景上。

## 冷热怎么分

默认块长 1024 点，采样率 48000 Hz，播放预算 21.33 ms。滤波器长度 512 点，左右耳各一套，一个方向大约 4 KB。卷积沿用现有的展开内核。一路声音只作为对照，用来确认混合退化为单套系数时结果正确，并写明它省下的时间相对 21.33 ms 可以忽略。主实验是多路。

三层存放：

- 热。当前用到的和紧挨着的方向，放进常量内存。容量大约 64 KB，大约十几个方向。每小段计算直接从这里读。
- 温。这一圈网格上其余方向，放在显存里。命中时拷进热区，不再从主机传送。
- 冷。网格上没有的方向，留在主机。未命中时整套系数送上显卡，再进入热区。

现有系数是各方向互不相关的随机噪声，混两个随机方向没有意义。改成随方位平滑变化的简单滤波器：方位越偏，一路的延迟和增益按固定规律变，另一路相反。这样混合有明确的标准答案，又不必解析 SOFA 文件。标准答案是在 CPU 上用双精度做同样的混合再卷积。误差用相对这个标准答案的信噪比，不要求等于某次真实人头测量。

两种做法仍然要对照。重送：需要换方向的每一路，每小段都从主机拷一套新系数。混合：方位落在热区里相邻两套之间时，只上传一个混合比例，在显卡上把两套系数按比例相加，再卷积。未命中热区但温区有，只在显卡内部换一套。冷区未命中才重送。

留几个热方向，用同一套多路运动来扫。例如 2、4、8、16 个。16 个已经顶到常量内存附近，再多就放不进热区，多出来的只能留在温区。报告画出重送次数、端到端时间和信噪比随热方向个数的变化，取重送少、时间短、误差还可接受的那一档，作为近似最优。不声称是数学上的唯一最优。

## 多路怎么动

主实验至少 8 路和 32 路。每一路的方位各自变化，不是一起转同一个角度。

- 多数路慢转。每小段转 1 度。热区盖得住时应该只传混合比例。
- 少数路甩头。一下跳到热区和温区都没有的方位。这一路这一段必须从主机重送，其余路仍混合。
- 一路不动，作为单路对照，不拿它的省时比例当应用结论。

每段记录端到端时间的中位数、99 分位和最大值，超过 21.33 ms 的段数，重送了几路，以及相对标准混合的信噪比。预热 20 段，计时至少 1000 段。

## 不做什么

不重测块长、阶数和四条通路，也不把以前“方位不动、只比几路谁更快”的扫描再跑一遍。不把“从 8 个声源起显卡更快”写成新结论。不把“整张显存装不下短系数”写成问题，4060 装得下。不做耳机试听，不把 WSLg 的播放延迟算进 21.33 ms。不上 OpenCL。不读课程文档里的例程。不做嵌入式片上内存那一版，课程研究点 6 在这里只借用冷热分层，层次是常量内存、显存和主机。

## 备选工作

下面两件不改变主问题。都做的话，在主实验之外大约再加一周。

网格疏密。热区个数固定时，温区网格改成每隔 5 度、15 度、30 度。网格越疏，慢转时越容易未命中，误差越大。

两种混合。一种是先把两套系数按比例相加，再做一次卷积。一种是两套系数各卷积一次，再把两路输出按同一比例相加。时间和波形误差分开报。第二种乘法多一倍，更接近 CPU 上“为了声音连续而算两次”的做法；第一种几乎不多算乘法，省下的是传送。

## 工作量和代码

主实验大约三周。卷积、计时和误差函数已有。

- 随方位变化的系数，以及显卡上两套系数的混合：约两天。
- 热、温、冷三层和热方向个数的扫描：约一周。
- 多路运动（多数慢转、少数甩头）接上重送和混合：约一周。
- 汇总表和写进报告：约三天。

代码放在现有 C++ / CUDA 工程里，不新开语言。主机侧新增方位发生器、混合比例和热区是否命中的判断。设备侧在已有卷积前增加系数混合；热区放常量内存，装不下的方向放全局内存。结果表写到 `results/motion_results.md`。

## 做完要能回答的话

多路里多数在慢转、少数在甩头时，留 2、4、8、16 个热方向，哪一档重送最少、端到端最短，信噪比还过得去。单路对照里，省下的时间相对 21.33 ms 有多小，用来说明为什么主实验必须是多路。甩头的那一路有没有从主机重送，而不是用一套错误的邻近系数硬混。不动的那一路，混合退化为单套系数，误差应和原来的浮点卷积同一量级。备选若做了，再回答网格变疏以后未命中和误差怎么变，以及先混合系数再卷积、和先卷积再混合输出，哪一种更省时间。
