# 实时块约束下移动声源头相关脉冲响应的系数重传与设备端混合

头在转时，方向系数要不要每一小段都重新送到显卡。头一转，声音的方向就变了，描述这个方向的那套短滤波器也得换。现在的做法是每一小段都从电脑内存把新系数送到显卡，光传送就要大约 54 微秒，和做乘法差不多久。另一种做法是事先把附近几个方向留在显卡里，头只转了一点点时，在显卡上把相邻两套系数按比例混出来，不再传送。这个工作就是比较这两种做法：哪一种更不容易把这一小段的播放时间用完，混出来的波形又和标准混合差多少。转得太远、显卡里没有那个方向时，再退回重新传送。CPU 和显卡谁做乘法更快，只用来决定这一小段放在哪边算，不再当作要证明的结论。

测量仍在现有 WSL2 和 RTX 4060 上进行。GPU 的启动和拷贝要经过 Windows 转发，绝对微秒数不能写成裸机规律。比较在同一台机器上完成，两种做法都被加上同一截转发时间，快慢差额仍然有效。

## 和已有工作的关系

前人把两件事分开做了，没有放在“这一小段必须按时播完”里比较。

方向怎么混才像真的。[Cuevas-Rodríguez 等人的 3D Tune-In 工具包](https://doi.org/10.1371/journal.pone.0211899)用分段频域卷积做实时双耳渲染，方位不在测量网格上时，用附近的头相关脉冲响应配出来（PLoS ONE，2019）。[Ramos、Cobos、Bank 和 Belloch](https://doi.org/10.1109/LSP.2017.2741724)把整套头相关传输函数收成可以并行的二阶滤波节，参数可以线性插值，并在 GPU 上同时渲染很多路声音（IEEE Signal Processing Letters，2017）。他们比的是方向像不像、能撑多少路，默认系数已经在计算设备上。

显卡适合算很长的混响和很多路，不适合每一小段都重新开工。[Wefers 的博士论文](https://doi.org/10.18154/rwth-2015-02185)把实时卷积分成均匀分段、非均匀分段和整段傅里叶变换，并讨论了滤波器随时间变化的情形（亚琛工大，2015）。[Gardner](https://aes.org/e-lib/browse.cfm?elib=7957)在 1995 年指出，冲激响应的开头若也拿去等一次大变换，延迟会先被变换块长吃掉（JAES）。[Rosseel 和 van Waterschoot](https://arxiv.org/abs/2509.04390)在很长混响上测到，块长大于 128 点后 GPU 分段卷积才能实时（2025 年预印本）。[Renney、Gaster 和 Mitchell](https://nime.org/proceedings/2020/nime2020_paper39.pdf)量过 GPU 音频的启动和搬运底噪大约 0.1 毫秒（NIME，2020）。[Carvalho、Ilic 和 Sousa 的综述](https://doi.org/10.1145/3830900)把这些结果收在一起：短滤波器、小音频块留给 CPU，长滤波器和很多路交给 GPU（ACM Computing Surveys，2026）。[Neidhardt、Klein、Knoop 和 Köllmer 的 pyBinSim](https://aes.org/e-lib/browse.cfm?elib=18721)把直达声、早期反射和后期混响拆开，长的那段可以放在 CUDA 上（AES 142nd Convention，2017；程序在 [GitHub](https://github.com/tuil-emt/pybinsim)）。这些工作换方向时假定换完就继续算，没有量过每一小段重送一套 512 点系数会不会把播放预算用完。

本工作不发明新的听感模型，也不重复“谁更快”的扫描。它把已有的传送代价和已有的“邻近方向可以混合”接在同一个截止时间上。

## 两种做法

默认块长 1024 点，采样率 48000 Hz，播放预算 21.33 ms。滤波器长度 512 点，左右耳各一套。卷积沿用现有的展开内核和“历史留在显存”的通路。

重送。每一小段根据当前方位选出一套系数，从主机拷到显卡，再卷积。这就是现在方位实验已经在做的事。

显卡内混合。事先把一圈离散方位留在显卡里，例如每隔 5 度一套。当前方位落在两套之间时，只上传一个混合比例，在显卡上把两套系数按比例相加，再用相加的结果做卷积。标准答案是在 CPU 上用双精度做同样的混合再卷积。误差用相对这个标准答案的信噪比，不要求混合结果等于某个“真实人头测量”。

现有系数是各方向互不相关的随机噪声，混两个随机方向没有意义。改成随方位平滑变化的简单滤波器：方位越偏，一路的延迟和增益按固定规律变，另一路相反。这样混合有明确的标准答案，又不必解析 SOFA 文件。

第三条是规矩，不是第三种卷积。若当前方位离显卡里最近的已有方向近，就混合；若跳到显卡里没有的区域，这一段改回重送。近和远的分界用角度，先取网格间距的一半，再在报告里说明改这个分界会怎样。

## 三种头的运动

每种运动都跑“总是重送”和“能混就混”。

- 不动。方位一直在网格点上。两种做法都不该多传送。用来确认混合比例为 0 或 1 时，结果和单套系数一致。
- 慢转。每小段转 1 度，转过好几格。大多数段落在两套已有系数之间，应该只传一个比例。
- 突然甩头。方位一下跳到网格外很远的地方，再停住。跳的那一段必须重送；停住之后回到混合或单套系数。

每段记录端到端时间的中位数、99 分位和最大值，以及超过 21.33 ms 的段数。慢转和甩头另外报告相对标准混合的信噪比。预热 20 段，计时至少 1000 段。

## 不做什么

不重测块长、阶数和四条通路，也不把以前的声源数扫描再跑一遍。不把“从 8 个声源起显卡更快”写成新结论。不做耳机试听，不把 WSLg 的播放延迟算进 21.33 ms。不上 OpenCL。不读课程文档里的例程。

## 备选工作

必做范围是一路声音、一种混合、一套网格。下面三件用来把工作量加到和课程里一个研究点差不多，问题不变。三件都做大约再加两周，总共约三周。不做也不影响必做部分能回答的那几句话。

网格疏密。除了每隔 5 度留一套，再做每隔 15 度和每隔 30 度。同一种慢转下，看混合误差和重送次数怎么变。网格越疏，能混的段越少，误差越大。

两种混合。一种是先把两套系数按比例相加，再做一次卷积。一种是两套系数各卷积一次，再把两路输出按同一比例相加。时间和波形误差分开报。第二种乘法多一倍，但不用先改系数。

多路一起转。不止一路。有的路每段只转 1 度，就混合；有的路突然甩远，就重送。统计这一整段还来不来得及播完。这不是重做“几路声音谁更快”的旧扫描，旧扫描里方位是不动的。

## 工作量和代码

必做大约一周到十天。卷积、计时和误差函数已有。

- 随方位变化的系数，以及显卡上两套系数的混合：约两天。
- 三种运动脚本，接上已有的重送路径：约两天。
- “近则混合、远则重送”的规矩和汇总表：约两天。
- 把结果写进一节报告：约一两天。

代码放在现有 C++ / CUDA 工程里，不新开语言。主机侧新增一个小的方位发生器和混合比例计算；设备侧在已有卷积前增加系数混合。结果表写到 `results/motion_results.md`。

## 做完要能回答的话

慢转时，显卡内混合比每段重送少多少时间，信噪比是多少，欠载有没有增加。甩头时，规矩有没有在该重送的那一段去重送，而不是用一套错误的邻近系数硬混。不动时，混合退化为单套系数，误差应和原来的浮点卷积同一量级。备选若做了，再回答网格变疏以后误差和重送次数怎么变，两种混合哪一种更省时间，以及多路里有的慢转、有的甩头时整段还来不来得及。
